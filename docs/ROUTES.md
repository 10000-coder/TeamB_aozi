# Pages

The reference is a Next.js app with six kinds of page. This repo reproduces all
of them, with two different techniques depending on how much the page varies per
URL.

| Page | Technique | Source |
|---|---|---|
| `/` | ported React (generated sections + data model) | `src/App.tsx`, `src/sections/`, `src/components/` |
| `/docs`, `/flywheel`, `/profile`, `/launch` | ported React, one component per layout variant | `src/sections/routes/*.tsx` |
| `/t/<address>` (47 pages) | prerendered snapshots of the captured DOM | `public/t/<address>/index.html` |

## Navigation

The top bar (`.family`, Coins, Porch talk, How to launch, Docs, Flywheel,
Profile) and the in-page links are handled by `src/useSiteChrome.tsx` +
`src/useLocation.ts`:

- the clone's own routes navigate client-side through the History API, the way
  the reference's Next.js `<Link>` does;
- `/#coins` and `/#porch` scroll to the section markers the reference itself
  uses (`[data-anchor="coins"]`, `[data-anchor="porch"]` — the reference has no
  `id` attributes anywhere, so `src/useAnchors.ts` resolves hashes against the
  same `data-anchor` markers, adding nothing to the DOM);
- `/t/<address>` pages are real files, so they get a document load;
- external links (X, Pons, DexScreener, Blockscout) keep their default
  behaviour. Nothing in the clone links out to the original site.

## The four top-bar pages

Generated by `tools/gen_route_pages.py`, which runs `tools/html_to_jsx.py` over
each captured DOM. Every page is emitted once per layout variant
(desktop/mobile × light/dark) because the reference inlines per-theme colours,
and inline style strings pass through `sx()` verbatim so nothing is re-authored
by hand. Each page's own stylesheet is diffed against the landing page's and only
genuinely new rules are added (`src/styles/route-*.css`), so the bundled CSS
cannot change how the landing page renders.

The generator is deterministic: re-running it in a clean environment over the
committed captures (`reference/routes/*.html.gz`) reproduces the committed
`.tsx` files byte for byte (verified by SHA-256 on all four pages and all four
stylesheets).

## The 47 token pages

`/t/<address>` is heavily data-driven, and the 47 captures fall into **18
distinct DOM shapes** — the trades table appears only when there are trades, the
quote asset may be SPY or ETH, graduation state changes the progress block and
the layout around it, and so on. Modelling that by hand would mean inventing
structure the reference does not have, so these pages ship as prerendered
snapshots produced by `tools/build_token_pages.py`:

- framework scripts and the RSC flight payload are dropped (~50% of each page);
- assets are rewritten to the clone's own paths (`/i`, `/img`, `/twimg`,
  `/fonts`);
- each page's stylesheet is hoisted into one shared file (`public/t/pg-*.css`)
  plus the shared `@font-face` block (`public/t/face.css`);
- a small script reproduces the reference's own theme-toggle and `data-anchor`
  hash behaviour.

All four layout variants stay in the markup, exactly like the reference, so
theme and breakpoint switching work with no JavaScript involved.
